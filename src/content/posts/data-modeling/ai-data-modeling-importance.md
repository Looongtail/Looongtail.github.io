## AI가 데이터를 이해하려면 먼저 데이터의 의미가 정리되어야 한다

생성형 AI가 기업 시스템 안으로 빠르게 들어오면서 데이터 활용 방식도 바뀌고 있다. 예전에는 사용자가 대시보드를 열고, 조건을 선택하고, 필요한 리포트를 직접 확인하는 방식이 일반적이었다. 이제는 “지난달 지역별 매출 흐름을 설명해줘”, “이 KPI가 왜 떨어졌는지 원인을 찾아줘”처럼 자연어로 데이터를 묻는 방식이 늘어나고 있다.

이 변화는 단순히 화면이나 사용 방식의 변화만 의미하지 않는다. 기업 입장에서는 AI가 어떤 데이터를 기준으로 답을 만들고, 어떤 지표 정의를 신뢰하며, 어떤 업무 맥락을 따라 판단할 것인지가 중요해진다. 결국 AI 활용의 품질은 모델 자체뿐 아니라, 그 모델이 바라보는 데이터 구조와 의미 체계에 크게 좌우된다.

그래서 데이터 모델링은 다시 중요해지고 있다. 과거의 데이터 모델링이 테이블 구조, 정규화, 성능, 관계 설계 중심이었다면, AI 시대의 데이터 모델링은 여기에 더해 “AI가 이해할 수 있는 비즈니스 의미를 어떻게 설계할 것인가”라는 문제까지 포함하게 되었다.

## 데이터 모델링의 중심이 구조에서 의미로 확장되고 있다

기존 데이터 모델링은 주로 데이터를 안정적으로 저장하고 조회하기 위한 구조 설계에 초점이 있었다. 어떤 엔터티가 있고, 어떤 관계가 있으며, 어떤 키로 연결되는지를 정리하는 것이 핵심이었다. 이는 여전히 중요하다. 기업 시스템에서 데이터 구조가 흔들리면 리포트, 인터페이스, 분석 시스템도 함께 흔들리기 때문이다.

하지만 AI 기반 분석 환경에서는 구조만으로는 충분하지 않다. 예를 들어 “매출”이라는 단어 하나만 봐도 주문 기준인지, 출하 기준인지, 청구 기준인지에 따라 값이 달라질 수 있다. “고객” 역시 계약 고객, 청구 고객, 실사용 고객, 그룹 고객 등 여러 의미로 쓰일 수 있다. 사람은 회의나 문서로 맥락을 맞출 수 있지만, AI는 이런 의미가 명확히 정리되어 있지 않으면 그럴듯하지만 잘못된 답을 만들 수 있다.

따라서 앞으로의 데이터 모델링은 테이블과 컬럼의 구조를 정의하는 일을 넘어, 지표의 의미, 업무 용어, 계산 방식, 데이터 사용 규칙을 함께 설계하는 방향으로 확장되고 있다. 이 변화가 최근 시맨틱 레이어와 메타데이터 관리가 다시 주목받는 이유다.

## 시맨틱 레이어는 BI를 넘어 AI의 공통 언어가 되고 있다

시맨틱 레이어는 데이터와 비즈니스 언어 사이의 해석 계층이다. 사용자는 “매출”, “재고”, “수요”, “납기 준수율”처럼 업무 용어로 질문하지만, 실제 시스템 안에서는 여러 테이블, 조인 조건, 필터, 집계 로직이 함께 작동한다. 시맨틱 레이어는 이 간극을 줄여준다.

과거 시맨틱 레이어는 주로 BI 도구에서 많이 다뤄졌다. Power BI, Tableau, Looker 같은 분석 도구에서 지표 정의를 재사용하고, 사용자별로 일관된 리포트를 제공하기 위한 목적이 컸다. 그러나 생성형 AI가 데이터 분석 과정에 들어오면서 시맨틱 레이어의 역할은 더 넓어지고 있다.

AI가 자연어 질문에 답하려면 어떤 테이블을 봐야 하는지, 어떤 컬럼이 어떤 의미인지, 어떤 지표 정의를 적용해야 하는지 알아야 한다. 이때 시맨틱 레이어는 AI가 참조할 수 있는 비즈니스 의미의 기준점이 된다. 결국 시맨틱 레이어는 더 이상 BI 전용 모델이 아니라, BI와 AI가 함께 사용하는 기업 데이터의 공통 언어로 바뀌고 있다.

## 메타데이터는 문서가 아니라 실행 컨텍스트가 되고 있다

많은 기업에서 메타데이터 관리는 오랫동안 문서화 업무로 여겨졌다. 테이블 설명, 컬럼 설명, 담당자, 생성 주기, 데이터 출처 등을 정리하는 작업이었다. 물론 이 자체도 중요하지만, 실제 업무에서는 문서가 최신 상태로 유지되지 않거나 분석 과정에서 충분히 활용되지 못하는 경우가 많았다.

AI 시대에는 메타데이터의 성격이 달라진다. 메타데이터는 사람이 참고하는 설명 문서에 머무르지 않고, AI가 쿼리를 만들고 답변을 구성할 때 사용하는 실행 컨텍스트가 된다. 컬럼 설명, 과거 쿼리 로그, 데이터 계보, 품질 규칙, 업무 용어사전이 AI의 판단 재료로 활용될 수 있다.

이 관점에서 데이터 카탈로그, lineage, business glossary, metric catalog는 단순 관리 도구가 아니라 AI 활용을 위한 기반 플랫폼으로 볼 수 있다. AI에게 데이터를 잘 설명해주려면, 먼저 기업 내부에서 데이터에 대한 설명이 구조화되어 있어야 한다.

## 실제 사례는 AI 모델보다 정리된 데이터 의미가 중요하다는 점을 보여준다

최근 공개된 사례들을 보면 공통점이 있다. 성공적인 자연어 기반 데이터 분석은 단순히 강력한 LLM을 붙이는 방식으로 만들어지지 않는다. 그보다 중요한 것은 AI가 신뢰할 수 있는 데이터 의미 체계를 제공하는 것이다.

Mercedes-Benz Korea는 Databricks와 함께 “Talk to Data” 파일럿을 진행하면서, 500개 이상의 KPI 정의를 AI가 활용할 수 있는 시맨틱 레이어로 정리하는 접근을 공개했다. 여기서 중요한 점은 챗봇 자체가 아니라, 기존 BI와 AI가 같은 KPI 정의를 바라볼 수 있도록 의미 계층을 정리했다는 점이다.

Uber의 QueryGPT 사례도 비슷한 메시지를 준다. 자연어로 SQL을 생성하는 내부 도구를 운영하면서, 사용자가 더 쉽게 데이터를 조회할 수 있도록 했다. 하지만 이런 도구가 제대로 작동하려면 테이블 구조, 컬럼 의미, 과거 쿼리 패턴 같은 맥락 정보가 함께 필요하다.

LinkedIn의 Text-to-SQL 사례는 이 흐름을 더 분명하게 보여준다. LinkedIn은 내부 데이터 분석 챗봇을 만들면서 데이터베이스 메타데이터, 과거 쿼리 로그, 위키, 코드 등을 knowledge graph로 연결하는 방식을 연구했다. 이는 AI가 SQL을 잘 만들기 위해서는 스키마 정보뿐 아니라 조직의 업무 맥락과 데이터 사용 패턴까지 필요하다는 점을 보여준다.

## 데이터 모델러의 역할은 의미 체계 관리자로 확장된다

AI가 SQL을 작성하고 ERD 초안을 그려주는 시대가 되면 데이터 모델러의 역할이 줄어들 것처럼 보일 수 있다. 실제로 반복적인 작업 일부는 AI가 빠르게 도와줄 수 있다. 테이블 설명 초안 작성, 컬럼 설명 추천, SQL 변환, 모델 문서화, 변경 영향도 분석 같은 작업은 AI와 잘 맞는다.

하지만 핵심 판단은 여전히 사람의 몫이다. 어떤 지표를 공식 기준으로 삼을 것인지, 어떤 데이터가 마스터인지, 어떤 관계를 표준 모델로 인정할 것인지, 어떤 예외를 업무 규칙으로 반영할 것인지는 AI가 자동으로 결정하기 어렵다. 이는 조직의 업무 방식, 책임 구조, 의사결정 기준과 연결되어 있기 때문이다.

따라서 데이터 모델러의 역할은 단순히 ERD를 그리는 사람이 아니라, 기업의 데이터 의미 체계를 설계하고 관리하는 역할로 확장될 가능성이 높다. 데이터 구조를 설계하는 능력뿐 아니라, 업무 용어를 정리하고, 지표 정의를 표준화하고, AI가 활용할 수 있는 메타데이터 품질을 관리하는 역량이 더 중요해질 것이다.

## AI 확산은 기업 데이터 아키텍처의 기준을 바꾼다

AI 기반 데이터 활용이 확산되면 기업 데이터 아키텍처도 영향을 받는다. 기존에는 데이터 웨어하우스, 데이터 마트, BI 리포트가 주요 소비 채널이었다. 앞으로는 여기에 AI 에이전트, 자연어 분석 도구, 업무 시스템 내 Copilot 기능이 새로운 소비 채널로 추가된다.

이때 중요한 것은 각 채널이 서로 다른 지표 정의를 사용하지 않도록 하는 것이다. BI 리포트의 매출과 AI 답변의 매출이 다르면 사용자는 AI를 신뢰하기 어렵다. 따라서 데이터 아키텍처는 단순히 데이터를 많이 모으는 방향이 아니라, 공통 지표와 의미 계층을 중심으로 여러 소비 채널을 연결하는 방향으로 설계되어야 한다.

또한 AI가 데이터를 직접 조회하거나 쿼리를 생성하는 경우에는 거버넌스도 더 중요해진다. 권한, 데이터 계보, 품질 검증, 민감 정보 통제, 쿼리 결과 검증이 함께 설계되어야 한다. AI 활용을 확대하려면 데이터 플랫폼, 보안, 거버넌스, 모델링이 분리된 과제가 아니라 하나의 아키텍처 관점에서 다뤄져야 한다.

## 데이터 모델링은 AI-ready 설계로 이동한다

앞으로 3~5년 동안 데이터 모델링의 중요한 방향은 AI-ready 설계가 될 가능성이 높다. 여기서 AI-ready란 단순히 데이터를 벡터DB에 넣거나 챗봇을 붙인다는 의미가 아니다. AI가 신뢰할 수 있는 지표 정의, 업무 용어, 관계 정보, 품질 기준, 접근 권한을 함께 제공할 수 있는 상태를 말한다.

이 흐름에서는 데이터 계약, 모델 테스트, lineage, metric catalog, business glossary 같은 요소가 더 중요해진다. 특히 여러 부서가 같은 데이터를 다르게 해석하는 조직일수록, AI 도입 전에 의미 체계를 정리하는 작업이 필요하다. 정리되지 않은 데이터 위에 AI를 얹으면 답변 속도는 빨라질 수 있지만, 의사결정 품질은 오히려 흔들릴 수 있다.

결국 AI 시대의 데이터 모델링은 “데이터를 저장하기 위한 설계”에서 “데이터를 올바르게 이해시키기 위한 설계”로 이동하고 있다. 이는 데이터 조직뿐 아니라, 현업 부서와 IT 조직이 함께 다뤄야 할 과제다.

## 좋은 AI 활용은 좋은 데이터 모델에서 시작된다

AI가 기업의 데이터 활용 방식을 바꾸고 있는 것은 분명하다. 하지만 그 변화의 핵심은 AI가 모든 것을 대신해준다는 데 있지 않다. 오히려 AI가 제대로 일하려면 기업 내부의 데이터 구조와 의미가 더 명확해야 한다.

데이터 모델링은 이제 과거의 설계 산출물이 아니라, AI 시대의 핵심 기반이 되고 있다. 테이블과 컬럼을 잘 설계하는 것뿐 아니라, 지표의 정의를 표준화하고, 업무 용어를 정리하고, AI가 활용할 수 있는 메타데이터를 관리하는 일이 중요해지고 있다.

기업 입장에서 지금 봐야 할 것은 “어떤 AI 도구를 도입할 것인가”만이 아니다. 우리 조직의 데이터는 AI가 이해할 수 있을 만큼 정리되어 있는지, BI와 AI가 같은 지표를 바라보고 있는지, 데이터 의미와 권한과 품질 기준이 함께 관리되고 있는지를 점검해야 한다.

좋은 AI는 좋은 데이터 모델에서 시작된다.
그리고 앞으로의 데이터 모델링은 사람이 데이터를 이해하기 위한 설계를 넘어, 사람과 AI가 같은 의미로 데이터를 이해하기 위한 설계가 될 것이다.
